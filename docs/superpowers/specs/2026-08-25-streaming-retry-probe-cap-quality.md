# Freegate: Стриминг-ретрай, лимит пробинга, проверка качества

> Дата: 2026-08-25

## Goal

Три фичи надёжности Freegate-прокси:
1. **Стриминг-ретрай по таймауту первого токена** — если streaming-провайдер молчит 5 сек, fallback к следующему.
2. **Лимит параллельного health-пробинга** — пакеты по 8 вместо 30 одновременных запросов.
3. **Проверка качества ответа** — отклонять ответы короче 5 символов (мусор/обрыв), не только пустые.

## Архитектура

Все три фичи — изменения в `server.js`. Каждая самостоятельна, тестируется отдельно, коммитится отдельно.

### Фича 1: Стриминг-ретрай по таймауту первого токена

**Проблема:** сейчас для streaming-запросов заголовки 200 пишутся сразу (server.js:380), до получения первого токена. Если провайдер вернул 200 но молчит — клиент висит пустым стримом, fallback невозможен.

**Решение:** для streaming-провайдеров (кроме `provider.reasoning === true`) не писать заголовки сразу. Буферизовать до 5 секунд:
- Если за 5 сек пришёл хотя бы один контент-токен → писать заголовок 200, промыть буфер клиенту, дальше стримить как обычно.
- Если за 5 сек токенов нет → записать failure, `continue` к следующему провайдеру.
- Провайдеры с `provider.reasoning === true` (or-ox-alpha) не буферизуются — стримят сразу (они легитимно думают 10с+).

**Реализация:** в цикле провайдеров streaming-ветку (server.js:379-437) заменить на буферизованную:
```javascript
if (isStreaming && result.stream) {
  if (provider.reasoning) {
    // Reasoning-модели думают долго — стримим сразу.
    res.writeHead(200, {...});
    result.stream.pipe(cleaner).pipe(res);
    return;
  }
  // Буферизуем до первого токена (макс 5 сек).
  const firstTokenTimer = setTimeout(() => {
    // Таймаут — заголовки ещё не отправлены, можем fallback.
    failAndContinue(key, 'first-token timeout');
  }, 5000);
  // ... накапливаем буфер, на первый токен отдаём заголовки + буфер.
}
```

**Детали:**
- Буфер хранит сырые SSE-чанки. На первый контент-токен: `clearTimeout`, `res.writeHead(200)`, записать накопленный буфер, продолжить поток.
- Если поток закончился до первого токена (сразу `[DONE]` без контента) — тоже failure + continue.
- На ошибку потока до первого токена — failure + continue.
- Хелпер `failAndContinue` инкапсулирует recordFailure + errors.push + recordRecent + continue.

### Фича 2: Лимит параллельного health-пробинга

**Проблема:** `healthCheck()` запускает все проверки через `Promise.allSettled` разом (server.js:113-115). 30+ одновременных fetch-запросов при старте.

**Решение:** обрабатывать пакетами по 8:
```javascript
const CAP = 8;
for (let i = 0; i < due.length; i += CAP) {
  const batch = due.slice(i, i + CAP);
  await Promise.allSettled(batch.map(([key, provider]) => checkProvider(key, provider)));
}
```
Полностью остаётся параллельным внутри пакета, но не более 8 одновременных сетевых вызовов.

### Фича 3: Проверка качества (короткий ответ)

**Проблема:** сейчас отклоняется только пустой ответ (`!hasContent`). Провайдер может вернуть «» после чистки, или мусор в 1-2 символа.

**Решение:** расширить порог: непустой ответ **короче 5 символов** после stripThink/clean тоже считается мусором.
- Non-stream: в guard (server.js:355-371) заменить `!hasContent(result.data)` на `!hasContent(result.data) || isTooShort(result.data)`.
- Streaming: если полный стрим собрал < 5 символов — не кэшировать (заголовки уже отправлены, fallback невозможен, но хотя бы не кэшируем мусор). Это уже частично есть (`full.trim().length > 0`), усилить до >= 5.

**Новый хелпер** в lib/clean.js:
```javascript
// Ответ короче MIN_ANSWER_LEN символов считается мусором (обрыв/один токен).
const MIN_ANSWER_LEN = 5;
function isTooShort(data) {
  if (!data || !Array.isArray(data.choices)) return true;
  const msg = data.choices[0]?.message;
  const content = typeof msg?.content === 'string' ? msg.content.trim() : '';
  const reasoning = typeof msg?.reasoning === 'string' ? msg.reasoning.trim() : '';
  return (content + reasoning).length < MIN_ANSWER_LEN;
}
```

## Критерии успеха

- Streaming-провайдер, молчащий >5 сек, не вешает клиента — fallback к следующему.
- Reasoning-провайдеры (ox-alpha) стримят без задержки.
- Health-пробинг не создаёт больше 8 одновременных запросов.
- Ответы короче 5 символов отклоняются как мусор (non-stream fallback, streaming не кэшируется).
- 57+ тестов, npm publish, Docker push.
